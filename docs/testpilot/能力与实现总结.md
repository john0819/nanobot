# nanobot 测试 Agent 二开能力总结

更新日期：2026-10-15。项目名称：TestPilot。

## 1. TRD 是否全部实现？

**没有。基础 Agent 闭环和多项工程保障已落地，完整测试业务闭环与企业交付仍有缺口。**

目前可以接收测试任务，让真实模型调用受控工具、按需检索知识、执行已审核测试，
根据真实产物生成经过校验的报告，并处理任务等待、重启恢复、审批和取消。
尚不能概括为“给任意项目一个需求，就能自主生成测试、定位根因、提交缺陷的完整平台”。

## 2. 已具备哪些能力？

| 能力 | 当前实现 |
|---|---|
| 模型与工具循环 | 复用 nanobot AgentRunner/Provider，模型可以多轮调用工具、观察结果并继续；已接 DeepSeek 实测 |
| 测试计划 | 支持有界 Plan、计划版本和行动范围校验；计划不能扩大执行权限或 Job 预算 |
| 代码与变更信息 | 读取审核 manifest 内的固定 Git commit/blob、代码片段；可配置只读 GitLab diff/CI 查询 |
| RAG 知识检索 | 接入 qa-kb-service，按需检索、身份绑定、ACL、版本化引用与无证据降级 |
| 真实测试执行 | 固定网关 suite，以及审核 Git manifest 声明的 pytest suite；独立 Docker Runner 执行并产出 JUnit/日志 |
| 结果分析 | 解析真实用例结果、失败项、跳过与未执行范围，读取有界产物片段；失败不自动等于确认产品缺陷或根因 |
| 可信报告 | 校验目标 SHA/环境/suite、证据 hash、执行终态、计数和模型声明；无证据或错误声明进入 NEEDS_REVIEW |
| 持久任务 | PostgreSQL 保存 Task/Run/Operation/Attempt、Checkpoint、事件和 outbox；支持历史查询 |
| 恢复与异步等待 | Worker 释放后由 Scheduler 查询 Job；支持工具轮及兼容 provider 私有状态恢复，避免重复创建 Job |
| 人工控制 | 审批、暂停/恢复、取消、私有补充输入；显式复跑创建新 Run，保留旧失败报告和原预算 |
| 经验 Memory | 失败观察形成候选，独立审核后使用；支持个人/项目范围、TTL、撤销、版本审计和来源复核 |
| 权限与隔离 | JWT/OIDC 服务端校验、角色/资源范围、审批内容 hash 绑定；容器非 root、只读、无网络、资源限额 |
| 上下文与防循环 | 模型输入预算、完整工具轮投影、负面证据保护、产物分页、重复观测与 A-B 震荡检测 |
| 存储与观测 | 本地/S3 内容寻址产物、读回 hash 校验、产物核查 CLI、脱敏 Trace、权限保护的 Prometheus 指标 |
| 使用入口 | Task API、SSE 事件、最小控制台，以及 API/独立 Runner/Scheduler CLI |

## 3. 基本的 Agent 功能都具备了吗？

**面向受控测试任务，主要基础能力已经具备；自主测试的完整业务能力尚未齐全。**

- 已有：模型推理与工具选择、多轮执行、观察反馈、有限规划、RAG、Memory、上下文管理、任务恢复和人工介入。
- 有边界：工具集合、目标、测试 suite 和执行权限由服务端准入；模型不能自由更改断言、扩大目标或执行任意代码。
- 尚缺：需求到受审核测试代码生成、完整失败诊断与缺陷提交闭环、主动补问、报告修复轮和正式模型效果评测。
- 动态工具召回和测试任务 SubAgent 属于进阶项，目前默认关闭，不能算已完成。

上游 nanobot 提供 Agent Loop、模型适配、工具基础设施及通用 Skills/MCP 等能力。
本次二开的重点是测试领域工具、持久任务、副作用治理、执行证据、权限隔离和工程验证。
上游已有通用工具或 SubAgent 代码，不等于它们已经在 TestPilot 中完成治理、接入和验收。

## 4. 主要技术点

1. **持久恢复与并发控制**：PG 事务、SKIP LOCKED、租约/epoch fencing、状态版本 CAS、Checkpoint 和事件/outbox。
2. **副作用治理**：Operation/Attempt 分离、持久幂等键、固定外部 Job 身份、UNKNOWN 仅查询、取消与 deadline、Runner 槽位限制。
3. **执行与结论分离**：执行器产生事实，模型提出候选声明，确定性 Evidence Gate 决定可发布内容。
4. **可追溯目标与产物**：Git commit/blob/manifest/镜像固定，SHA256 内容寻址、S3 远端读回校验、版本化报告。
5. **上下文与恢复协议**：按 tool_call_id 配对恢复、私有 transcript/provider state、Runtime 指纹、完整工具组预算投影。
6. **权限与人审**：身份/角色/资源校验、审批绑定具体目标和内容、派发事务消费审批、RAG ACL、Memory 独立审核。
7. **异步运行与可观测性**：Agent Worker 和 Job Scheduler 分离、SSE 重连、模型轮/工具耗时与 token Trace、指标接口。

## 5. 已验证到什么程度？

- TestPilot 回归 **119 项通过**，最近上游兼容集 **66 项通过**；lint 和 TestPilot 严格类型检查通过。
- DeepSeek 真实端到端：健康场景 **4 PASS**；缺陷场景 **3 PASS / 1 FAIL**，两份报告均正确通过证据校验。
- 真实模型驱动的 Git/独立 Runner 链路：Job 创建后 kill/restart，恢复同一 Job，报告通过，7 个产物 hash 核对通过。
- 确定性 Provider 的 10 并发真实容器验收：10 个报告通过，每个任务只有一个外部 Job。
- 模型验收期间也出现过两次拒绝报告，已记录并补充类型约束、恢复及诊断；不能据此声称模型输出永不出错。
- OIDC/GitLab 部分为同协议模拟测试；本次真实模型链路不包含 RAG，没有完成公司服务联调或大规模模型评测。

## 6. 距离 TRD 完整交付还缺什么？

| 方向 | 主要缺口 |
|---|---|
| 测试业务闭环 | CasePlan/测试代码生成与审核、断言来源校验、多 suite、有限执行重试、request_id 日志诊断、缺陷草稿审批与外部提交 |
| Agent 治理 | 主动 WAITING_INPUT、报告修复轮、版本化工具目录、熔断、动态工具召回、可选 SubAgent |
| 预算与权限扩展 | token/费用总预算、完整用户/项目/全局配额、通用多项目路由、浏览器 OIDC 登录/session |
| 部署运维 | 完整服务 Compose、保留策略/GC/孤儿清理、备份恢复演练、OTLP 跨服务 Trace/告警 |
| 效果验收 | 80 条分层业务数据、模型评测/消融、完整故障矩阵、持续压测与人工报告审查 |

当前适合定位为：**基于 nanobot、具备真实执行和证据校验能力的工程化测试 Agent，已打通受控测试闭环，正在补齐自主测试业务与企业交付能力。**
